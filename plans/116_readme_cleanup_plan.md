# 116 - Make the README user-oriented (cleanup developer/contributor content)

Status: implemented (docs-only change)

## Problem

The root [`README.md`](../README.md:1) has grown to ~900 lines and mixes three
audiences in one document:

- **User / operator / self-hoster / API consumer** — what the product is, its
  features, how to run it, how to configure it, where to consume the data.
- **Contributor / developer** — prerequisites, running the backend binary
  locally, a full "Running tests" section, and per-provider development notes.
- **Internal architecture** — job-scheduler and heartbeat semantics, persistent
  provider state, provider-message caps, asset-storage/MinIO internals, cache
  headers, name-uniqueness rules, and a complete REST + BFF endpoint listing
  (which is already auto-generated by Swagger/OpenAPI).

Most of that developer/internal content has a dedicated home already:

- per-provider behaviour lives in the adapter READMEs under
  [`backend/src/adapter/driven/`](../backend/src/adapter/driven) (Münster, Bonn,
  Hamburg, Leipzig, Eco-Counter each ship a `README.md`),
- the full option/var reference lives in the commented
  [`config.toml.example`](../config.toml.example:1),
- the API surface is documented by the auto-generated OpenAPI/Swagger-UI,
- contributor workflow and gates live in [`CONTRIBUTING.md`](../CONTRIBUTING.md:1)
  and [`agents.md`](../agents.md:1).

## Goal / Decisions

1. [`README.md`](../README.md:1) targets the **user** only: what the project is,
   what it offers, how to run it (Docker Compose), how to configure it, and where
   the API/OpenData + interactive API docs are.
2. Contribution-related content is **removed from the README** and the README
   ends with a short **Contributing** section pointing to
   [`CONTRIBUTING.md`](../CONTRIBUTING.md:1) (and [`agents.md`](../agents.md:1) /
   [`plans/`](../plans) for the workflow).
3. Valuable developer content currently only in the README is **preserved**: the
   prerequisites + local-run instructions (Rust/Node/Postgres, running the
   backend binary) move into a new **Local development** section in
   [`CONTRIBUTING.md`](../CONTRIBUTING.md:1). Deep architecture/internals that
   are duplicated elsewhere (adapter READMEs, config template, Swagger) are
   trimmed, not re-located.
4. Essential **operational** documentation stays in the README, kept short:
   configuration basics (database + data sources + optional services), quick
   start, the service URL table, and a brief OpenData/API description.
5. No product behaviour, code, or configuration is changed — docs only.

## New README outline

1. **Intro** — what Bike-Counter is and which cities/sources it covers.
2. **Features** — user-facing: interactive map, station detail page (overview
   stats, timeframe selector, bar charts, weekday/hour-of-day radars,
   per-channel share), station summary page, "exclude new stations from trends"
   calculation setting, responsive layout + dark mode. One line on the tech
   stack (React + Rust + PostgreSQL, Docker Compose).
3. **Quick start** — copy `config.toml.example`, `make run` /
   `docker compose up --build`, open <http://localhost:8081>; note that the
   first start builds the self-hosted basemap (network needed, a few minutes).
4. **Services and URLs** — table (web app, BFF API, public REST API,
   Swagger-UI, health endpoints).
5. **Configuration** — `config.toml` from the tracked template: database
   settings, the supported data sources/provider types (Münster, Bonn, Hamburg,
   Leipzig, Eco-Counter v1/v2/web) with a pointer to `config.toml.example` and
   the adapter READMEs, optional `[asset_storage]`/`[opendata_storage]`/`[maps]`
   sections, automatic migrations, scheduled background jobs.
6. **Open data & API** — public `/api/v1`, OpenData bulk export under
   `/api/v1/opendata` (daily/monthly parquet/csv.gz/json), frontend-only
   `/api/bff`, and a pointer to Swagger-UI / the OpenAPI JSON document.
7. **Contributing** — link to `CONTRIBUTING.md` (+ `agents.md`, `plans/`).

## Content moved / removed from the README

| Old README content | Disposition |
|---|---|
| Prerequisites, Start the database, Run (backend binary via `cargo run`) | Move to [`CONTRIBUTING.md`](../CONTRIBUTING.md:1) "Local development" |

| API overview + BFF endpoint listing | Replaced by a short surfaces paragraph; endpoints remain fully documented in Swagger/OpenAPI |

| Running tests | Already covered by [`agents.md`](../agents.md:25) gates + `CONTRIBUTING.md` step 7 |

  `make test`, `make coverage`, `make test-playwright`) do not apply.
- Manual review: rendered README no longer contains contributor/internal
  content beyond the Contributing pointer and short operational notes.
- [`CONTRIBUTING.md`](../CONTRIBUTING.md:1) keeps its adapter guide and gains the
  Local development section.
- [`plans/README.md`](../plans/README.md:11) registers this plan; a short
